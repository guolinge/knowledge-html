17 个积木的完整 DSL（示例都是真的，能直接跑）

围栏内是 YAML。行内支持 Markdown（**粗体**、`代码`）和裸 HTML。

可运行示例：notes/blocks-cheatsheet/note.md

通用：行内强调

全文都是 **加粗** 时，等于没有重点 —— 术语、结论、坑长得一模一样。 所以把三个语义拆成三种颜色：

写法 语义 颜色
==文字== 关键结论 / 最该记住的一句 蓝
!!文字!! 坑 / 反直觉 / 注意 橙
++文字++ 正确做法 / 推荐 绿
**文字** 句子内的重音（降级用，不再承担强调职责） 加粗，不变色
`文字` 术语 / 标识符 等宽 
HTTP 缓存 ==默认只按 URL 区分==，不看请求头。

!!`Cache-Control: no-cache` 不是「不缓存」，是「每次都要去校验」。!!

++要彻底不存用 `no-store`；要存但每次校验用 `no-cache`。++

一屏之内不要超过 3 个 ==。 到处都是重点等于没有重点。

反引号里的内容不会被解析（`a == b` 安全），带空格的 a == b 和 ==== 这种空内容也不会被误判。

坑：**URL** 后面不要紧跟中文标点

❌ 然后开 **http://localhost:5173/**。

渲染出来是这样：

❌ 然后开 **<a href="http://localhost:5173/**%E3%80%82">…</a>

加粗丢了，而且 href 里带着 ** —— 链接是坏的。

根因在 linkify-it：它只在 * 位于字符串末尾时才把它从 URL 里裁掉。 后面跟了个中文句号，* 就不再是末尾了，于是 **。 一起被算进 URL。

写法渲染结果建议
**http://x/**（行尾）✅ 正常可以用
**http://x/**。❌ href 被污染改成下面两种之一

两个改法（npm run check 会直接告诉你这两条）：

① 去掉加粗，用等宽 —— URL 本来就更适合用反引号
   然后开 `http://localhost:5173/`。

② 保留加粗，在 `**` 前面垫一个空格
   然后开 **http://localhost:5173/ **。
⚠

不要试图改渲染器修这个。

把 * 从 URL 字符集里拿掉的代价是：http://x/**/y 这种合法 URL 会被切坏。 而且 linkify-it 没有暴露可配项（实测 md.linkify.__opts 是空的）。

一个检查比一个聪明的渲染器更安全。 npm run check 里有 lintLinkifyStars，会直接报出行号和两种改法。

通用：tone 配色

所有积木的 tone 都取这几个值，控制色条、标签和强调色：

tone 用在哪
muted 中性、背景信息（默认）
blue 主流程、当前关注点
violet 加工/转换环节
green 结果、正确做法
amber 注意、待优化
red 错误、危险、删除

要点：

  • 不用写坐标。 节点用 flex 排版，连线由 app.js 测量后画成 SVG 路径 —— 文字多长、屏幕多窄都会自动重算。
  • 连线走节点背后，所以看起来是「从盒子到盒子」，不用手动算边框交点。
  • 同排节点之间的连线会自动画成左右方向的曲线。

能力边界（重要）

flow 是「测量 + 直线/贝塞尔连接」，没有边路由引擎。所以：

画得好看 会翻车
DAG：从上往下、有分支汇合 大量交叉边（比如「第一个节点直接连到最后一个节点」）
干净的状态机（每个状态只连相邻的） 稠密的状态机（任意两个状态都可能连）
3~5 行 10 行以上，连线会穿过中间的节点

四条可判定的规则（不是抽象提醒）

下面的形状 npm run visual-check 会直接报出来，不用等看截图：

形状会怎样怎么改
一条边跳过了整整一行它必然从那行穿过去让边只跨相邻两行
同一 row 两个节点各自往下连连线从对方框上穿过去改成纵向一条链
两个节点之间的边带标签标签比间隙宽就压在框上要么拆到不同 row，要么把标签改短
两条反向边（A→B 和 B→A）两个标签画在同一个空隙里，叠成乱码现在会自动上下错开 15px

阶梯 + 公共出口：这个形状 flow 画不了

   [第一个判定]
        ↓
   [第二个判定] ──→ ┐
        ↓          │ 每条「是」都要跨好几行
   [第三个判定] ──→ ├─→ [公共出口]
        ↓          │
   [第四个判定] ──→ ┘

阶梯节点在同一列上，而所有「是」边都得跨 2~4 行到公共出口 —— 必然穿过阶梯。 实测 5 种排法（出口放第 1 / 2 / 5 / 6 行、阶梯节点挪行）全部无解。

这是「不上 dagre/elkjs」的直接代价：100KB~1.5MB 换自动布局，而「单文件发人」是这个仓库的核心价值。

✅

遇到这种拓扑怎么办：

  1. 拆成两张图 —— 阶梯一张（只画「否」的下行链），出口一张
  2. 改用 compare —— 「形态 → 怎么处理」本来就是一张对照表
  3. 真的画不了又不想改 → 加进 tools/visual-baseline.json， 它会照旧报（⚠）但不阻塞推送

翻车了怎么办：

  1. 拆成两张图 —— 主流程一张，异常分支一张
  2. 用 compare 列转移表 —— 状态机的完整转移用表格表达反而更清楚
  3. 别硬画。一张挤成一团的图比没有图更糟。

为什么不上 dagre / elkjs 做自动布局？因为它们 100KB~1.5MB， 而「单文件发人」是这个仓库的核心价值。用体积换一点排版，不划算。

7. seq —— 时序图

什么时候用：讲调用链 —— 谁在什么时候调谁、等不等回复、返回什么。

记法依据 UML 2.5：参与者横排，时间向下流，消息是水平箭头。 核心约束是「每条消息线必须水平或向下」—— 所以不可能出现向上的箭头（回复除外）。

客户端
API 网关
数据库
1POST /orders
2SELECT * FROM orders
3结果集
4200 OK
重试
键 说明
participants[].id 唯一标识，消息靠它引用
participants[].label / sub 参与者名字 / 等宽小字（窄屏会隐藏 sub）
participants[].tone 配色（显式写了会覆盖 kind 的默认色）
participants[].kind 同 flow 的语义类型，带图标
messages[].from / to 两端参与者。相同就是自调用
messages[].label 消息文字
messages[].note 序号或旁注，画在箭头上方
messages[].kind 箭头样式，见下
messages[].tone 消息着色（箭头和标签一起变色）
messages[].gap 这条消息前面额外留白（px）。用来表达「这一步慢」
segments[] 时间段框：{ from, to, label }，from/to 是消息序号（1 起）

激活条是自动的，不用写。 它按「这个参与者收到过什么、发出过什么」推导： 取所有相关消息的 y 区间。纯发起方（先发后收，比如客户端）不画 —— 激活条表示「在处理」，而它在等待。

顶层加 grid: true 会有背景网格。

箭头样式（kind）：

kind 画成 语义
sync（默认） 实心三角箭头 同步调用，等回复
async 空心箭头 异步调用，不等
reply 虚线 + 空心箭头 回复
self 右侧小环 自调用（from 等于 to 时自动识别）

要点：

  • 参与者按 grid 均分，lifeline（虚线）和箭头由 app.js 测量后画成 SVG。
  • 一行 = 一条消息，行高固定，所以时间轴是等距的。
  • 参与者不要超过 5 个，否则列会太窄。
  • 最后一个参与者的「自调用」，标签压到 5~6 个字以内。 自调用的标签是绝对定位的（left: lx + 58px; max-width: 38%）， 越靠右的参与者，留给它的宽度越小 —— 最右边那个可能只剩 130px 左右。 写长一点就会换行，然后溢出那一行容器。细节挪到正文里，图上只留两三个字。
  • 序号和消息文字都对齐到「箭头的实际中点」，不是容器中点 —— 所以三条泳道取相邻两条时，标签也指得准。
  • 序号在消息文字上方（纵排，不会压住）。
  • 自调用那一行分三段：序号在 lifeline 左边、环在中间、消息在右边。
  • segments 的框会自动给时序图顶部留 30px 余量 —— 这段余量加在 DOM 上 （.seqd-body 的 padding-top），不是加在 SVG 坐标里。 两边的坐标必须一起动，只动 SVG 会让箭头和消息文字错开。 时间段框的标签画在框顶上方 7px，而参与者卡片和第一行是紧挨着的（间隙 0）， 不留余量的话标签只能落进卡片或第一行，两边都撞。

  • 目录树、类层次、对象组成、调用栈都适合。纯线性链条用 lane-stack，别用这个。

四个作业，六种算法

config.jobs[]：id / arrive（到达时刻）/ burst（需要运行多久）/ priority（1 最高）。 控件现算，不预先烤结果 —— 换作业集只改这几行。

state 含义 颜色

文件的第 N 个字节，inode 靠什么找到它

滑块是对数刻度（maxLog: 12 表示拉到底 = 10¹² 字节）， 否则前 40KB 只占滑块的前 0.001%，根本拖不到。

它算的是 Unix inode 的「直接 + 多级间接」那一套。换个领域也能用， 只要那个东西是「按大小分档、每档代价不同」—— 例如缓存层级、分片路由。

link-refcount —— 删一个名字会发生什么

点「删除」，看引用计数怎么动

names[].kind 只影响显示（origin 与 hard 在语义上完全平等，这正是要讲的点）。 symlink 是可选的 —— 给了它，控件会多画一条独立的 inode 线， 用来说明「软链接有自己的 inode，目标是死是活它都在」。

gmp-lab —— 一个真的会跑的迷你调度器

讲「有队列的调度器」：点「跑一步」，看每个 P 取 G、偷 G、被阻塞 G 挂到 netpoller。 它不是动画 —— 背后就是一份简化过的 schedule()。

GMP 调度台

gomaxprocs 是 P 的个数，goroutines 是 G 的总数。 ioRatio 控制多大比例的 G 会先去等网络，seed 固定随机种子让结果可重放。

创建时所有 G 都落在 P0 的队列里（新 G 挂在创建者身上）—— 这是刻意的，因为「一边倒」才是真实常态，也让工作窃取立刻可见。

换个领域也能用：只要那个东西是「一堆任务 + 若干执行许可 + 本地/全局两级队列」。

handoff-lab —— 同样是等，代价不一样

讲「两条路径的成本差」：一根滑块拖动「同时阻塞的数量」， 左右两栏的 M 数量分道扬镳。

同样在等，M 的数量不一样

左栏 = 等待被某种 poller 吸收（M 数量不变），右栏 = 每个等待都要一个执行体陪着沉下去 （M 线性膨胀）。gomaxprocs 是基线，max 是滑块上限。

它在讲一件很通用的事：「等」有两种 —— 能被事件驱动接管的，和不能的。 缓存未命中、锁竞争、外部 API 调用，都能套这个模型。

gmp-lab —— 一个真的会跑的迷你调度器

讲「有队列的调度器」：点「跑一步」，看每个执行许可怎么取任务、怎么从别人那儿偷、 被阻塞的任务又挂到哪儿去。它不是动画 —— 背后就是一份简化过的 schedule()。

ipc-flow-lab —— 几种机制的数据流并排跑

讲「同一件事，不同实现路径」：每一列都是同构的三格（发送方 / 中转站 / 接收方）， 点「下一步」同步推进，看数据停在哪一格、计数怎么变。

同一份数据，三种走法

控件里写死了三个机制（管道 / 消息队列 / 共享内存），因为它们的步数被刻意对齐成一样 （0~3 步），这样三列才能同步对比。想换领域的话，得改 app.js 里那份 COLS。

每一步要提供：at（数据在哪一格：a / k / b）、copy（累计拷贝次数）、 sys（累计系统调用次数）、what（这一步在干什么）。 每列还要给中转站的 kLabel / kNote —— 有差别的只有中间那一格，所以它值得单独写。

runtime-timeline —— 一行一个进程，看谁常驻谁一次性

讲「生命周期」：横轴是时间，一行一个进程。想说明「A 是长期依赖、B 只是来一趟」时， 一条时间轴比任何分层图都清楚 —— 长度差得一眼就看见。

创建、重启、删除：谁在，谁不在
  • procs[].spans 是左闭右开的区间数组 —— 一个进程可以有多段（上面 containerd 在 5~6 之间断了一下，用来表达「重启」）
  • 生命周期只有 1 格的进程会自动标上「只存在一瞬间」
  • steps[].at 是时间点，推着走的时候：还没出现的行整体变淡、已经消失的行保留它的条子 （那样才看得出它曾经存在过多久，否则「一次性的」和「从没出现过」就分不清了）

note 是点开给好奇的人看的：某一行还活着时才显示。 面板上的 what 是主线，note 是「它到底是个什么角色」。

数据驱动的写法（config）

上面三个控件都用 config，作者只写 YAML，不写 HTML：

  • panes → 双栏日志式（配合日志型控件）
  • html → 作者手写标记，控件只负责接线
  • config → 控件自己渲染整个 body（推荐）

五种图都验证过能走我们的管线（node tools/archify.mjs 直接吃它们的 spec）。 下面这些是「管线怎么搭的」，不是「怎么写 spec」：

  • SVG 是预先抠好提交进仓库的，构建时不调 archify —— 否则别人 clone 后没有 archify 就构建不了。
  • tools/archify.mjs 会给 archify 的 CSS 变量加 --af- 前缀。 archify 在 :root 定义了 32 个变量，名字和我们完全一样，不隔离会把整页变深色。
  • assets/archify-embed.css 是全站共用的，按 assets/arch/*.svg 的 class 并集生成 —— 所以多张图共存不会互相删样式，重复跑也不会变。
  • 两边都用 data-theme 属性，所以深浅色天然同步，不用额外处理。
  • 找不到 SVG 时会直接报错并告诉你怎么生成，不会静默画空白。

title / sub 顶部标题与副标题（sub 渲染成等宽小字）
high / low 轴两端的标注，画在底部
segments[] 从上到下就是高地址到低地址（顺序有意义，别乱排）
segments[].label / sub 主文字 / 说明。sub 是放机制和数字的地方
segments[].size 高度权重（默认 1），不是真实字节数
segments[].dir up / down，画一个增长方向标记
segments[].addr 右侧的地址标注
segments[].mark 右侧的旁注，比如「线程独享」/「可共享」
note 底部一句话

要点：

  • mark 那一列是这张图最值钱的地方。 共享 / 独享、可读 / 可写这类属性， 竖着排一列，读者扫一眼就拿到了边界 —— 散在正文里要读三段。
  • size 是权重不是比例。真实比例会让大部分段小到看不见 —— 地址空间里 99% 是空的，按真实比例画出来就是一张空白。
  • 地址用 0x 前缀 + 等宽字体渲染，所以写 0x7fff_ffff_ffff 这种带下划线的形式最易读。

同类形状都能用：磁盘分区、ELF 文件布局、TCP 头部字段、位域切分、栈帧。

17. summary / raw

一句话总结

CDC 负责把变化实时通知出来；Flink 负责加工变化。

raw 块直接输出 HTML，是一次性排版实验的逃生口，不要长期使用 —— 它绕过了积木系统，换肤和校验都管不到它。

YAML 常见坑

裸标量里不能出现 : （冒号 + 空格），会被当成新的键：

# ❌ 解析失败
desc: 注意: 这里有问题
# ✅ 三种写法
desc: "注意: 这里有问题"
desc: '注意: 这里有问题'
desc: |-
  注意: 这里有问题

> 开头的标量会被当成折叠块：

sub: "WHERE updated_at > ?"    # ✅ 加引号

多行文本用块标量，比转义引号干净：

note: |-
  第一行
  第二行，可以写 **Markdown**

列表里的行内映射要加空格：- { k: v } 而不是 - {k: v}。

值以 * / & / ! 开头必须加引号 —— YAML 里它们是别名 / 锚点 / 标签的起始符：

# ❌ Unresolved alias: *这里以星号开头**会炸
- { title: x, desc: **加粗**开头 }
# ✅
- { title: x, desc: "**加粗**开头" }

键以 * / & / ! 开头也要加引号 —— 而且报错完全看不出是同一回事：

# ❌ 报「保留字符」或「序列对齐」或「隐式键」，就是不说「你的键以星号开头」
rows:
  - **机制**（因果关系）:
      - ...

# ✅
rows:
  - "**机制**（因果关系）":
      - ...
⚠

但块标量里面不算。

text: | / body: | 的内容是字符串 —— 里面写什么都没关系：

text: |
  - 这一行以短横线开头，完全合法，因为它在字符串里

工具第一版没管这件事，一下误报了 23 处。 误报会阻塞全仓库的 check，比漏报还麻烦。

npm run check 有预检会直接报这两条（块式和流式都覆盖，且会跳过块标量内部）。

围栏里要放代码块时，外层用四个反引号：

❌ 外层 3 个反引号：内层的裸 ``` 会把外层提前闭合
````callout
text: |
  上面一段

  ```
  core ──┬──→ crowd
  ```

  下面一段 —— 这段会被当成代码块正文，**加粗** 字面显示
````

✅ 外层 4 个反引号：内层的 ``` 正常渲染成代码块
````callout
text: |
  上面一段

  ```
  core ──┬──→ crowd
  ```

  下面一段 —— **加粗** 正常生效
````
⚠

这个坑非常隐蔽：页面看着正常，只是后面的段落错位、**加粗** 字面显示。

因为剩下的 markdown 全被当成代码块的正文了 —— 你不会看到任何报错。

npm run check 有专门检查（lintFences）：发现「没有语言标注的代码块里 出现 markdown 强调标记」就报出来，并提示把外层换成四个反引号。

值里有 [ 或 { 时也要加引号：

# ❌ Rule[] 里的方括号会被当成数组起始
- { title: Rule[], desc: "..." }
# ✅
- { title: "Rule[]", desc: "..." }

值以反引号 ` 开头也要加引号（YAML 会当成保留字符）。

校验

npm run check    # 只校验不写文件；有问题退出码 1

会报出：YAML 解析失败（带文件和行号 + 原文回显）、未知围栏语言（积木名拼错的典型症状）、 meta.json 缺字段、缺 quiz。
