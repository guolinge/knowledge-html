02两条管线为什么分开

预览和快照是两条执行路径，图上它们是两根并排的竖管。分开的根据是资源与时效：预览是当场要答案的活查，留在 normal 资源组；快照是异步冻名单，进专用限额，慢一点不影响别人圈人。同一份 DSL、同一个编译器，出口不同 —— countSql / listSql 走左管，uidsSql 走右管。

边界线也讲了同一件事：下游用虚线外的领土表示 —— 洞察只交出 snapshotId，名单由下游拉取校验后落自己的库，洞察不替它管生命周期。

为什么预览和快照在图上是两根竖管，而不是一根？

预览是同步活查（normal 资源组，当场回人数和名单页）；快照是异步冻名单 （专用限额，CREATE JOB INSERT SELECT，状态机推进到终态）。 同一份 DSL、同一个编译器，出口不同 —— 合成一根会掩盖「导出不建快照、 预览不占快照配额」这两条资源边界。

组件包和协议包为什么是两个包？

组件包是 Vue + element-plus 的渲染层，协议包是零依赖纯 TS。 拆开后 BFF 能直接 import 同一份 DraftQuery 类型和 buildQuery， 组件和编译器共用一套错误码；类型断言 InsightQuery extends DraftQuery 保证历史 DSL 回显免转换。依赖方向一条直线：组件依赖协议，从不反向。

元数据读接口为什么要出两份投影？

组件版（无物理列、含停用项回显）驱动界面，编译版（Catalog，带表名列名） 供 SQL 解析。同一份 crm_dc_* 真相、两种安全等级：组件永远拿不到 物理映射，DSL 与 Doris 物理模型的解耦在接口层就完成了。
