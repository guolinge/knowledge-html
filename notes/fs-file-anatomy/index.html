01一句「一切皆文件」底下有什么

文件系统是操作系统里负责持久化数据的那部分。它管的事情很具体：把用户的东西存到磁盘上，让断电之后它们还在。

基本单位是文件。文件怎么组织、怎么命名、怎么摆到磁盘上，不同的组织方式就是不同的文件系统（Ext4、XFS、NTFS……）。

Linux 有一句名言：

一切皆文件。

这不只是修辞。下面这些完全不同的东西，在 Linux 里都归文件系统统一管：

这些「东西」本质上都是文件
普通文件 /home/a.txt
目录 /home/
块设备 /dev/sda，一整块硬盘
管道 两个进程之间那根竖线
socket 一条网络连接
同一套系统调用 open / read / write / close
学一次就够 dd if=/dev/sda 读硬盘，写法和读文件一模一样

好处很实在：多出来的设备类型不用再各造一套接口。 学一次 read，硬盘、管道、网络连接都能读。

那这样一套东西，底下的基本零件是什么？

02三样东西拼出一个文件

一个文件在操作系统眼里，是由三部分组成的：

索引节点（inode）

inode 记的是文件的元信息：

inode文件本体在操作系统里的档案
我是谁

inode 编号。每个文件一个，在同一个文件系统里唯一。

你在终端敲 ls -i 看到的第一列就是这个数。

我长什么样

文件大小、访问权限（rwx）、创建时间、修改时间、最后访问时间……

ls -l 显示出来的那堆东西，几乎全部来自 inode。

我的内容在哪

数据块的位置。这是 inode 最重要的一项。 文件真正的内容不在 inode 里，inode 只记「去哪儿找」。

第 ③ 篇整篇都在讲这一项怎么记。

inode 是文件的唯一标识，而且它存在磁盘上。 也就是说 inode 自己也要占空间，也要被管理。一个文件系统能存多少个文件，取决于它能分出多少个 inode，而这是格式化的时候就定下来的。

目录项（dentry）

目录项记的是文件的名字，以及它指向哪个 inode。

它和 inode 有一个根本区别：

对比项索引节点 inode目录项 dentry
记什么文件的元信息 + 数据块位置文件的名字 + 指向哪个 inode
存在哪磁盘上，持久保存内存里，内核维护的一个缓存
占磁盘空间吗占，inode 区是磁盘上单独的一块区域不占，它只活在内存
一一对应吗一个 inode 对应一个文件多个目录项可以指向同一个 inode

最后一行就是硬链接的全部原理：给同一个文件多起几个名字，只需要多写几条目录项。

目录项不是目录

这两个词长得像，但完全是两回事，很容易看错：

磁盘

目录

一种文件，持久存在磁盘上

它有自己的 inode，inode 指向自己的数据块，数据块里装的是 「名字 → inode 号」的对照表。

因为它是个文件，所以你能 vim 打开它，也能给它设权限。

内存

目录项

内核的一个内存结构，缓存解析结果

路径解析很贵：/a/b/c/d 要读四次目录。所以内核把已经解析过的 「这个名字对应哪个 inode」记在内存里，下次直接用。

它不是磁盘上的东西，重启就没了。

目录项记录的不一定是目录，也可以是一个普通文件。它的作用就是「记住一个名字解析到了哪儿」。

03一次读写的最小单位：扇区与块

磁盘读写的最小单位是扇区，传统上只有 512 字节。

但文件系统不按扇区干活。原因很直接：

单位大小如果按它读写会发生什么
扇区512 字节每读 1KB 要发 2 次请求，还要等两次寻道和旋转，效率极低
逻辑块4KB（Linux 默认）一次请求读写 8 个扇区，磁盘的机械动作被摊薄了

Linux 会把多个扇区组成一个逻辑块（也叫数据块），文件系统内部一律按块来算：

一个逻辑块 = 4KB = 8 个扇区
扇区 1 512B
扇区 2 512B
扇区 3 512B
…… 一直到扇区 8 剩下的都一样
文件系统只认块 分配、定位、记账都按 4KB 来

这个 4KB 后面会反复出现：inode 里记的是块号不是扇区号，位图里一位管的是一个块，一个索引块能装 1024 个块号（4096 ÷ 4）。换一个块大小，后面所有数字都要重算。

04磁盘被格式化成的三个区

格式化的时候，磁盘（或分区）会被划成三块区域：

区域 1 超级块 整个文件系统的说明书
块总数 这个文件系统一共多少块
块大小 一块多少字节
inode 总数 最多能存多少个文件
空闲块数 现在还剩多少
什么时候进内存挂载的时候
区域 2 inode 区 所有 inode 排在一起
inode 1 某个文件的全部元信息
inode 2 另一个文件的
…… 格式化时就分好的固定数量
什么时候进内存这个文件被访问的时候
区域 3 数据块区 文件真正的内容
数据块 4KB 一块
数据块 目录的内容也放这
…… 占磁盘的绝大部分

这三个区进内存的时机不一样，这一点容易忽略：

区域什么时候加载进内存为什么
超级块文件系统被挂载时操作系统一上来就得知道这个文件系统有多大、块多大，不然没法用
inode 区某个文件被访问时文件那么多，全加载进内存不现实，用哪个载哪个
数据块区读写到哪一块就载哪一块按需读，通常还会在内存里留一份副本（页缓存）

没人会把整个 inode 区加载进内存。一个有 100 万个文件的文件系统，光 inode 就要占掉几十上百 MB，而同一时刻真正在用的可能只有几百个。

修改一个文件的名字，需要改它的 inode 吗？

不需要。名字记在目录项里，inode 记的是元信息和数据块位置，里面没有文件名。 改名就是把原目录里那条「名字 → inode」改成新名字，inode 一个字节都不用动。 目录项为了效率经常缓存在内存里，改名字就更快了。

inode 为什么必须存在磁盘上，而目录项可以只在内存里？

inode 是文件的唯一标识，它记着数据块在哪，这个信息丢了文件就找不回来了，必须持久化。 目录项只是「某个名字解析到了哪个 inode」这个结果的缓存， 丢了可以重新读目录再解析一遍，所以不需要落盘。

为什么文件系统不直接按扇区（512 字节）读写？

因为磁盘最贵的动作是寻道和旋转。按 512B 读写会让每个小块都要付一次机械代价， 效率极低。把 8 个扇区合成一个 4KB 的逻辑块，一次请求就能拿走 8 倍的数据， 机械开销被摊薄了。这也是后续所有「块号、位图、索引数量」都以块为单位的原因。
