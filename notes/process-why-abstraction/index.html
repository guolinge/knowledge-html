「进程」不是设计出来的，是被逼出来的

先别背定义。把进程拿掉，让两个程序直接裸跑在同一块内存上——你会依次撞上四件人祸，而进程的每个零件都是被其中一件逼出来的。

01换个问法：不要进程，会出什么事

「进程 = 正在运行的程序」——这句话没错，但它只说了进程是什么， 没说进程为什么必须存在。

反着问一遍就清楚了：如果让两个程序直接裸跑在同一台机器上， 中间没有任何管理方，会出什么事？

答案是四件事，而且每一件都躲不掉。

人祸 ①

地址冲突

两个程序都从同一个地址开始放

A 和 B 都从 0x1000 开始放代码和数据 —— 因为写代码的人 不可能知道别人会占哪儿。

一加载就互相覆盖：后加载的把先加载的盖掉。

人祸 ②

越权访问

A 的一条 store 就能写进 B 的数据区

A 里一条普通的 mov [0x3000], 1 指令， 如果 0x3000 恰好是 B 的变量 —— 它就直接改掉了。

没有任何东西拦它，因为根本不存在「谁的内存」这个概念。

人祸 ③

长期占用

A 死循环，B 永远轮不到 CPU

CPU 只有一个。A 进了 while(1) 之后不会主动让出来， B 就永远等在那里。

这不是「B 慢」，是 B 根本没有机会开始。

人祸 ④

故障扩散

A 崩了，B 跟着崩，还说不清该杀谁

A 的野指针写穿内存，正好压在 B 的数据上，B 算出乱七八糟的结果。

更麻烦的是：没有一份账记录谁用了哪些资源， 所以连「把 A 干掉、留下 B」这个动作都做不到。

这四条不是「进程机制的缺点」，而是「没有进程机制时必然发生的事」。

02每个冲突，逼出一个机制

关键在这里：这四个机制不是一起设计出来的，是各自被一个具体问题逼出来的。 把它们和四件人祸对上，就能看出每个零件存在的理由：

人祸逼出来的机制它新划出的边界
地址冲突虚拟地址空间 + 页表每进程一张表，地址视图私有
越权访问特权级（用户态 / 内核态）系统调用是唯一的门
长期占用时钟中断 + 调度器时间片到期必须让出
故障扩散资源记账（PCB 的雏形）可单独清算、单独回收

注意最后一行和第二行、第一行有交叉：虚拟地址空间同时对付「地址冲突」和「故障扩散」 （因为越权访问被页表拦下时，故障就被关在了一个进程里）， 而资源记账独立解决了「说不清杀谁」。

所以更准确的说法是三件事，不是一个对一个：

机制它管什么
独立地址空间我有哪些内存，且只有我能用
受控执行我能跑，但进出内核的门和时间片都不归我管
资源边界我开过的文件、占过的内存被单独记账，可被单独清算

这三条就是后面所有内容的坐标轴。先把第一条展开 —— 它是全部机制里最不像「发明」的那个。

03独立地址空间：页表既是翻译器，也是隔离墙

图里有两组对照，值得分开看：

前两行（数据 x）是隔离。 A 和 B 的 x 虚拟地址都是 0x601000， 但页表把它们翻译到了不同的物理帧。A 写 1，B 写 2，各自毫不知情。

隔离能力不来自布局，而来自翻译。 进程里的地址全是虚拟地址， CPU 每次访存都要过页表；每进程一张页表，寄存器 PTBR 指向当前进程那张。 上下文切换时换 PTBR，等于给 CPU 换一个翻译器。

第三行（代码 text）是共享。 代码段是只读的 —— 这张图解释了为什么只读：

text 只读不是约束，而是一种省法。同一程序的多个实例既然不会改代码， 就可以让它们的 text 映射到同一批物理页。

同一套机制，两个方向：可写的东西分家，只读的东西合租。

🔑

一个常见的简化要澄清：「线程拥有栈、进程拥有堆」不是结构事实。

线程的栈同样位于进程地址空间内部（无非是 mmap 出来的一块区域）。 同进程的任何线程，在权限上都能读写别人的栈。

「私有」只意味着约定：由该线程维护、编译器与运行时保证别人不越界。

这个约定的反面很有意思：一旦被野指针破坏，故障就能跨线程传播 —— 这恰恰是「线程的故障域比进程大」的根因。第 3 篇会拿它当尺子用。

地址空间里从低到高详细长什么样（text / data / bss / heap / mmap / stack， 带 x86-64 的真实地址和增长方向），在《线程共享什么、独享什么》里已经画过， 这里不重复。这张图只讲「同一个地址为什么会落到两个物理帧」。

04「受限执行」：内核大部分时间不在场

前三件人祸对付完了，还剩「长期占用」。但这里藏着一个更根本的张力：

内核要能随时收回控制权（否则挡不住死循环）， 但用户程序每跑一条指令都让内核过一遍，性能会慢到不可用。

解法叫受限直接执行：让用户程序全速直跑，内核只守住几个「回收点」。

while (true) {
  enter_user_mode(proc->pc);   // 降特权级，跳回用户态断点，全速执行
  // 内核此刻是「不在场」的 —— 直到硬件抛回三类事件之一：
  switch (event) {
    case TRAP:   syscall_dispatch(proc);  break;  // 系统调用
    case FAULT:  handle_fault(proc);      break;  // 异常：非法地址 / 除零 / 缺页
    case TIMER:  schedule_next(proc);     break;  // 时钟中断：时间片到期
  }
}
回收点谁引发内核要做什么回来之后
TRAP 系统调用用户程序主动请求服务把请求转给对应的内核代码服务完就放回用户态，不换人
FAULT 异常非法地址 / 除零 / 缺页缺页就补页，段错误就终止该进程这一步直接决定了「谁能被单独杀掉」
TIMER 时钟中断硬件定时器，谁也没请求schedule()，挑下一个任务强制换人 —— 这是死循环的唯一破法

「受限」二字限制的不是用户程序能做什么，而是内核现身的时机。

⚡

为什么必须让用户程序直跑？

因为如果每条用户指令都要内核先解释一遍（这叫解释执行 / 陷阱模拟）， 每一次内存访问、每一次算术都要往返内核 —— 性能会掉几个数量级。

直跑换性能，三个回收点换控制权。这是操作系统里最基础的一笔交易。

这段伪代码的骨架，就是任何一个现代内核的调度入口。

05资源边界：从「说不清杀谁」到「能单独清算」

第四件人祸是最不起眼的那个：A 崩了，凭什么能留下 B？

因为内核给每个进程记了一份账。这份账在 Linux 里叫 task_struct， 在教科书里叫 PCB（进程控制块）。

它记的东西很朴素：

账目记了什么为什么必须有
身份与状态PID、当前状态没有 PID，「杀掉 A」这句话都说不出来
寄存器现场被换下 CPU 时的寄存器快照换回来的时候要知道从哪接着跑
地址空间页表在哪不然找不回「它的」那些内存
打开的文件文件描述符表不然进程退出时有一批 fd 泄漏在外面
调度信息优先级、时间片、在哪个队列调度器得能把它挑出来

有了这份账，「清算一个进程」才变成一个可执行的动作： 把它的地址空间还回去、把它的 fd 全关掉、把它占的内存标记为可用。

🗂

这份账本有一个现成的只读视图：/proc/<pid>/。

文件 里面是什么
/proc/<pid>/status 身份、状态、内存占用、凭证
/proc/<pid>/fd/ 它现在开着哪些文件（就是账目里那一栏）
/proc/<pid>/maps 地址空间里的每一段映射

排查「这个进程到底开了什么、占了什么」，全在这里。

Linux 里还有个 current 宏，免查表拿到「当前进程」—— 因为 90% 以上的系统调用第一件事就是取它。

06三件套合起来，就是「进程」

把散落的零件收进一个定义：

组成部分实体是什么谁在管
独立地址空间页表 + 各段的 VMA 描述每进程一张，换 PTBR 就换世界
受控执行至少一条执行流（主线程）进出内核靠 trap / 异常 / 时钟中断
资源边界PCB（Linux 里是 task_struct）可被单独调度、单独阻塞、单独清算

进程 = 程序 + 运行环境 + 执行流。

最后一项解释了一件很日常的事：同一个程序为什么能启动 N 次而互不干扰。 因为「运行环境」每个实例独立一份 —— 跑的是同一份代码字节， 各自的变量、打开的文件、执行进度互不相见。

这也是 PID 的含义：它标识的是一次运行实例，不是程序本身。 同一个 node 可执行文件可以对应成百上千个 PID。

世界静态的那份实例的那份谁把前者变成后者
gitcommit 对象 · 不可变，躺在 .git 里working tree · 可改、可删、一堆未提交的中间态checkout
进程可执行文件 a.out · 静态字节，躺在磁盘上进程实例 · 寄存器 / 栈 / 打开文件execve / 加载器

同一个 commit 可以在多个目录 checkout 出互不相干的工作区， 就像同一个二进制可以拉起互不相干的进程。

差异只在一处：working tree 的「状态」是文件内容，进程的「状态」是寄存器和栈 —— 那正是上下文切换要保存的东西。

「进程」这个抽象里，为什么必须有页表，光有虚拟地址不够吗？

不够，而且页表才是关键的一半。虚拟地址本身只是一串数字； 真正让它变成隔离的是「每次访存都要过页表翻译」这个动作。 每进程一张页表，两个进程的同一个虚拟地址 0x601000 就能落到不同的物理帧。 反过来说，同一份只读代码也可以让两个进程的页表都指向同一个帧 —— 复用同一套机制。 所以页表既是翻译器，也是隔离墙。

为什么不让内核「每条指令都检查一遍」，这样不是最安全吗？

因为性能会掉几个数量级。每条指令都往返一次内核，等于放弃直接执行。 实际做法是相反的：让用户程序全速直跑，内核只守住三个回收点 —— TRAP（系统调用）、FAULT（异常、缺页）、TIMER（时钟中断）。 「受限」限制的不是用户程序能做什么，而是内核现身的时机。 其中 TIMER 是唯一能破掉死循环的，因为它不依赖用户程序配合。

同事说「进程崩了不影响别人，因为每个进程有自己的内存」。这句话完整吗？

只说到了一半。独立的地址空间确实让越权访问被页表拦下，故障被关在一个进程里。 但「能留下别人、只清算这一个」还需要第二样东西：资源记账。 没有 PCB，内核连「A 用过哪些内存和文件」都答不上来，也就没法把它干净地回收。 两样合起来才成立：地址空间负责「别波及别人」，记账负责「能单独清算」。

线程的栈「私有」，这句话该怎么理解才不误导人？

它是一种使用约定，不是结构事实。线程的栈就在进程地址空间内部， 无非是 mmap 出来的一块区域；同进程的任何线程在权限上都能读写别人的栈。 「私有」的意思是编译器与运行时保证不越界，由该线程自己维护。 这个区别有实际后果：一旦野指针破坏了这个约定，故障可以跨线程传播， 整个进程一起崩 —— 这正是线程的故障域比进程大的根因。
