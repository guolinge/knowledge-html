## 01 · RIP 指的是「下一条」

`RIP` 是 x86-64 里的**指令指针**（Instruction Pointer），也叫**程序计数器**（PC，Program Counter）。它存着 CPU 接下来要执行的机器指令的地址。

名字随位数变，位置和作用不变：

```compare
first: 模式
head: [指令指针, 出现在哪]
rows:
  - 16 位 x86: ["`IP`", 8086 时代]
  - 32 位 x86: ["`EIP`", 保护模式]
  - 64 位 x86-64: ["`RIP`", 现在的桌面 / 服务器]
```

「`RIP` 存着下一条指令的地址」这句话是对的，但要补一个容易忽略的细节：**执行当前这条指令的时候，`RIP` 已经指向下一条了**。取指完成后就自增，这条指令后续的动作都在「`RIP` 已经指好下一条」的前提下进行。

这不是文字游戏，前面三篇里到处都用到了它：

- `call` 压进栈的，就是 `RIP` 当时的值 —— 也就是下一条；
- `syscall` 把「下一条」存进 `RCX`，回来时 `sysret` 再从 `RCX` 装回 `RIP`；
- `lea 0x12(%rip), %rdi` 算的是「下一条 + 0x12」，不是「这条 + 0x12」。

### 它不是等步长

x86 的指令长度从 1 字节到 15 字节不等。所以「`RIP` 每次加多少」得看这条指令有多长。`calc` 的真机反汇编，每条后面标了字节数：

```text
0x100000360  pushq %rbp              1 字节
0x100000361  movq  %rsp, %rbp        3
0x100000364  subq  $0x10, %rsp       4
0x100000368  movl  %edi, -0x4(%rbp)  3
0x10000036b  movl  -0x4(%rbp), %edi  3
0x10000036e  movl  $0x3, %esi        5
0x100000373  callq _add              5
```

`movl -0x4(%rbp), %edi` 和 `movl $0x3, %esi` 是同一条指令的两个形态，一个 3 字节一个 5 字节 —— 差在后者带了一个立即数。

## 02 · 谁在改 RIP

只有三类事件会改它：

| 事件 | `RIP` 怎么变 | 顺手还做了什么 |
|---|---|---|
| 普通指令执行完 | `RIP += 指令长度`（1–15 字节） | — |
| `jmp` / `jcc` | `RIP ← 目标`（条件跳转不成立时还是顺序下一条） | — |
| `call` | 先 `PUSH 下一条`，再 `RIP ← 目标` | 往栈上压返回地址 |
| `ret` | `RIP ← [RSP]`，`RSP += 8` | 从栈上弹返回地址 |
| 中断 / 异常 | 硬件把 `RIP` 存起来（多数情况压栈），`RIP ← 处理程序入口` | 保存现场 |
| `syscall` | `RCX ← 下一条`，`RIP ← IA32_LSTAR` | 切到内核 |
| `sysret` | `RIP ← RCX` | 回到用户态 |

后两条值得单独看一眼，因为它们是「`RIP` 被搬到别处」的典型：手册里写得很直白。

```callout
tone: muted
icon: 📖
quote: true
text: |
  SYSCALL invokes an OS system-call handler at privilege level 0. It does so by
  loading RIP from the IA32_LSTAR MSR (after saving the address of the instruction
  following SYSCALL into RCX).
```

也就是说：`syscall` 把「下一条」存进 `RCX`，再从 `IA32_LSTAR` 这个 MSR 里取出内核入口地址放进 `RIP`。回来的时候 `sysret` 反过来：`RIP ← RCX`。

==所有「跳转」的实质都是同一件事：把一个新地址写进 `RIP`==。区别只在「新地址从哪来」—— 指令里带着（`jmp rel32`）、寄存器里带着（`jmp *%rax`）、从栈上弹（`ret`）、从 MSR 里取（`syscall` / `sysret`）、或者由硬件按中断向量表算出（中断）。

## 03 · 为什么 `mov rip, rax` 不存在

把 `RIP` 当普通寄存器写，汇编器会直接拒绝。本机试的原文报错：

```text
$ clang -arch x86_64 -c bad.s
bad.s:4:14: error: %rip can only be used as a base register
  movq %rax, %rip
             ^~~~
```

「只能当基址寄存器用」—— 这句话把 `RIP` 的身份说清楚了：它不是 `RAX` 那样的通用寄存器，没有编号可以填进「目的操作数」那一栏。它只能出现在寻址表达式里当基址（`[rip + 位移]`），或者被控制流指令整体改写。

要**读出** `RIP` 的值，有两条合法路子，都不需要 `mov`：

```text
leaq  0(%rip), %rax       ; 7 字节：48 8D 05 00 00 00 00 —— 得到下一条指令的地址
call  1f                  ; 5 字节：E8 00 00 00 00 —— 跳到下一条
1: popq %rax              ; 把刚压进去的那个地址弹出来
```

第二条是早年 shellcode 找自己位置的经典写法（`call` 压「下一条」，紧接着 `pop`），现在有了 `lea` 就很少用了。两条的共同点是：**它们都没有真的「读一个叫 RIP 的寄存器」，而是让 CPU 在算地址时把 `RIP` 用进去**。

```callout
tone: violet
icon: 💡
text: |
  这不是权限限制，是编码限制。

  改 `RIP` 等于改控制流，所以 CPU 要求你走「有明确语义」的指令：`jmp` / `call` / `ret` /
  `iret` / `sysret`。==它们除了换地址，还各自带着该做的事（压栈、弹栈、换特权级、
  检查影子栈）== —— 这些是单给一个 `mov` 补不上的。
```

## 04 · RIP 相对寻址：64 位里到处都是它

规则一句话：`[RIP + disp32]` 的有效地址 = **下一条指令的地址 + 那个 32 位位移**。

本机一个能对账的例子（`probe-x86` 的反汇编）：

```text
0x100000595  leaq 0x12(%rip), %rdi    ; 7 字节，下一条是 0x10000059c
```

算一下：`0x10000059c + 0x12 = 0x1000005ae`。再看这个二进制里的字符串表：

```text
$ otool -v -s __TEXT __cstring probe-x86
00000001000005ae  ret = 0x%lx\n
```

字符串就躺在 `0x1000005ae`。==指令里只写了 `0x12` 这么小一个数，却指到了 2GB 范围内的任何地方== —— 因为基址是会变的 `RIP`，不是写死的常量。

为什么 64 位里到处都是这种写法：

- **位置无关代码（PIC / PIE）**。现在 macOS 和多数 Linux 发行版默认把程序编译成 PIE，加载地址每次运行都不同（ASLR）。机器码里不能写死绝对地址，只能写「相对当前位置多远」。
- **共享库**。`.so` / `.dylib` 被映射到哪个地址，链接时根本不知道，只能用相对位移。
- **编码更短**。64 位绝对地址要 10 字节（`movabs`）；`[rip + disp32]` 只要 7 字节。

这也是为什么反汇编里几乎看不到裸的全局地址：

```text
0x10000058e  movq  _ret_(%rip), %rsi   ; 读全局变量，也是相对的
0x100000595  leaq  0x12(%rip), %rdi    ; 取字符串地址
```

## 05 · AArch64 没有 RIP

Arm 把「当前执行到哪」放在 PC 里，但 PC **不是通用寄存器**，不能当 `mov` 的源或目的。本机试的原文报错：

```text
$ clang -arch arm64 -c pc.s
pc.s:11:11: error: unknown AArch64 fixup kind!
  mov x0, pc
          ^
```

（行号指向 clang 内部的临时汇编文件，不是你写的那一行，别去改第 11 行。）

要拿「当前地址」，用的是 PC 相对的两条指令：

```text
adrp x0, 0            ; 取 PC 所在页的基址（页对齐，4KB）
add  x0, x0, #0x5f4   ; 加上页内偏移
adr  x0, 1f           ; 或者短距离直接用 adr（±1MB）
```

本机反汇编里给 `printf` 传格式串就是这两条：`adrp` + `add`。思路和 `[rip+disp]` 一样 —— **不写绝对地址，写相对当前多远**，只是拆成了两条指令、页 + 页内偏移各管一段。

```compare
first: 对比项
head: [x86-64, AArch64]
rows:
  - 指令指针叫什么: ["`RIP`", "`PC`（不是通用寄存器）"]
  - 能直接读出来吗: ["不能 `mov`，但 `lea 0(%rip)` 可以", "不能 `mov`，但 `adr` / `adrp` 可以"]
  - 能直接写吗: ["不能，只能走跳转/调用/返回", "不能，只能走 `b` / `bl` / `ret` / `eret`"]
  - 相对寻址怎么写: ["`[RIP + disp32]`，一条指令", "`adrp` + `add`（页 + 页内偏移）"]
  - 返回地址存在哪: ["栈上（`call` 压的）", "`LR`（`x30`），需要时自己压栈"]
```

最后一行呼应第二篇：x86 的 `RIP` 在调用时被压进栈，Arm 的返回地址先进 `LR`。**「下一条在哪」这件事两个架构都要记，只是记在不同的地方。**

## 06 · 速查：容易记反的六件事

```checklist
tone: cross
items:
  - "`RIP` 存的是正在执行的那条指令的地址。—— 存的是下一条；当前这条已经在执行了。"
  - "`RIP` 每条指令固定加 1。—— 加的是这条指令的字节数，1 到 15 不等。"
  - "`call` 之后 `RIP` 会等于 `call` 的地址加 5。—— `call` 是跳到目标，不是落到下一条。"
  - "可以用 `mov rax, rip` 读出来。—— 汇编器直接报错，只能用 `lea 0(%rip)` 这类相对寻址。"
  - "`[rip + 0x12]` 里的 `0x12` 是相对这条指令的。—— 是相对**下一条**指令的。"
  - "AArch64 的 PC 和 x86 的 RIP 一样能随便读写。—— 同样不行，Arm 用 `adr` / `adrp` 代替。"
```

```summary
title: 一句话
text: |
  `RIP` 是「下一条要执行的指令地址」。它按指令长度自动前进，被跳转/调用/返回/中断整体改写；
  你能让它相对自己算地址，但不能直接给它赋值。
```

```quiz
- q: "为什么 `[rip + 0x12]` 算出来的是「下一条 + 0x12」，而不是「这条 + 0x12」？"
  a: |
    因为取指之后 `RIP` 就已经指向下一条了，指令执行时它保存的就是下一条的地址。
    所以位移是相对下一条算的 —— `call` 压进栈的也是同一个值，道理相同。
- q: "`mov rip, rax` 为什么不存在？"
  a: |
    `RIP` 不在通用寄存器的编号表里，不能作为 `mov` 的目的操作数 —— 本机汇编器的报错是
    `%rip can only be used as a base register`。要改它只能走 `jmp` / `call` / `ret` / `iret` / `sysret`，
    这些指令除了换地址，还各自负责压栈、弹栈、换特权级等配套动作。
- q: "同一份程序，为什么换个加载地址还能跑对？"
  a: |
    因为访问全局变量和常量时用的是 `[rip + 位移]`：位移写在机器码里不变，`RIP` 跟着程序一起平移，
    算出来的绝对地址也跟着平移，还是落在同一个变量上。写死绝对地址的代码换个基址就指空了。
- q: "AArch64 上想取「当前代码的地址」，该用什么？"
  a: |
    `adr`（±1MB 内）或 `adrp` + `add`（页基址 + 页内偏移）。PC 不是通用寄存器，
    `mov x0, pc` 汇编器会报错；返回地址则在 `LR`（`x30`）里。
```
